# T20 随机组合与批次复现（v7 设计）

**已确认的交互。** 初次生成时为工程建立种子。「用同一种子重新生成」复现最近一批的组合与顺序，「换一批」才取新种子。取消换批或生成失败时，仍可回到上一批。勾选几条再导出，沿用预览里对应的计划。每批最多 1,000 条。

**v6 基线。** 本地抽样在 `src/media.cjs`。画面、镜像、口播和包装已有有限组合，配乐在选完组合后另抽。例如，一个分镜只有一个候选、关闭镜像且配两首有效配乐，v6 最多生成一条。工程格式 v6 没有种子。预览编号用于找到内存里的计划，工程重开也会重分配素材编号。

| 规则 | 编辑时的结果 |
| --- | --- |
| 组合去重 | 按原分镜记录所选候选和镜像方向，再记录实际选择的整段或分段口播、配乐、启用的字幕样式及包装选项。同一批只接收一次相同选择。示例中的两首配乐可生成两种组合。固定字幕样式只占一种。封面抽帧、镜头乱序、智能裁切和随机效果由种子复现，不额外占用组合数。 |
| 候选偏好 | 每个候选可标普通、必选、降低出现率。先按启用和独听筛选；某分镜有可用的必选项时，每条成片都从这些项中选一个。多个必选项尽量轮换。低频项按普通项一半权重参与抽样，按权重尽量均衡。标记跟随时间线上的候选实例。 |
| 多样性 | 严格条件默认关闭。可要求任意两条在至少 N 个原分镜选用不同候选，也可要求相邻两条的实际开头镜头不同。仅换镜像或配乐不会增加分镜差异。条件冲突时保留满足要求的条目，显示实际条数并可调整条件。 |
| 组合空间与覆盖率 | 前后台共用同一套计数规则，以大整数计算应用轨道和候选筛选后的理论空间。生成前显示预计覆盖率，例如 200 ÷ 4,320 ≈ 4.6%；接近上限时提示余下的新组合少。生成后按实际条数重算。增加跨条多样性要求后，可取得的数量可能低于理论空间。 |

**可复现范围与风险。** 相同种子、算法版本、素材内容及设置应得到相同的有序计划，包括封面、镜头顺序、裁切和效果。随机决策使用可重建的分镜及候选位置、轨序与子工程标识，避免运行时素材编号、文件路径或批次编号影响结果。多样性搜索按固定顺序和尝试次数执行，以便重跑得到相同结果。可证明无解时说明冲突，达到尝试上限时显示「本次已找到 X 条」，并允许导出这些条目。

**工程格式与验收。** v7 保存最近成功批次的种子、抽样算法版本、多样性设置及候选标记。v1–v6 工程和旧草稿首次迁移时补种子，沿用已有素材和编辑参数，多样性默认关闭。首次覆盖时备份原文件为可独立打开的 `pre-v7` 副本。实施时核对同种子重跑、保存重开、素材重新定位、子工程选择顺序、倍速确认重试和勾选导出；用可穷举的小工程核对计数、去重与不可满足条件，再验证 1,000 条批次的操作响应。
