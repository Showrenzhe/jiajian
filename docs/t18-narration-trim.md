# T18 口播裁剪断点与静音参数

## 裁剪规则

此前，画面优先的整段和分段口播都在可用时长末尾硬切。v5 新工程默认采用「智能裁剪」。整段口播从实际起点算至成片末尾，分段口播从偏移后的起点算至所属分镜末尾。超长时，在截止前最后 500 ms 内先取最近的带时间戳的句末，其次取实测停顿中的断点。提前收声的空档保留画面及其他音轨。两种断点都找不到时在截止处硬切，仅淡出口播，默认 100 ms，可调 80–150 ms，最长为实际保留时长。[断点与时间映射](../src/ui/narration-trim.js)

口播优先的「佳剪」规则裁短相邻分段口播的接缝静音。「口播 → 成片设置 → 口播裁剪」中的阈值、最短静音和每侧保留余量默认分别为 −40 dB、120 ms 和 120 ms。时间线上「已裁短」的口播片段在悬停或键盘聚焦时显示「裁掉开头 X 秒 / 结尾 Y 秒」。[口播设置](voice.md#决定画面和口播的长度)

## 工程兼容

v5 工程与草稿保存裁剪方式和四个参数。v1–v4 打开时沿用旧规则，分段接缝每侧保留 25 ms，超长口播在截止处直接收声。用户可以在当前工程显式改用智能裁剪。首次覆盖旧文件前建立可独立打开的 `pre-v5` 备份。[工程格式与恢复](time-model.md#旧工程备份与恢复)

## 风险与验证

同一段录音可能经手动裁剪重复出现或改变播放顺序，直接平移原字幕会让第二次出现的台词错位。断点跟随实际选中的音频、手动保留区间、倍速、偏移和画面长度。实时草稿与成片计划按同一映射裁音、调整关联字幕及包装，固定时间线字幕保留原位。测试逐行核对字幕与所保留音频的交集，并用音调、静音及可解码成片区分句末、停顿和硬切，检查 80、100、150 ms 淡出。工程回归覆盖两种文件扩展名、冷草稿、只读打开、保存失败、并发保存和旧备份共存。[裁剪测试](../test/narration-trim.test.cjs) · [迁移测试](../test/project-format.test.cjs)
