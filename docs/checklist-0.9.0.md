# 佳剪 0.9.0 本地验收记录

## 给剪辑同事

安装内部离线包后，从首页「最近草稿」点击原草稿即可恢复编辑。若素材来自另一台电脑或共享盘，按缺失列表选择新素材目录。要复核此前截图中的第 3 分镜，请打开已修复该分镜画面范围的工程副本。原工程仍保留原先的手动摆放。

在同事原草稿副本上，104 项素材全部离线时也能进入剪辑台。修改音量、按 Ctrl+S、回首页再打开，27 个分镜、66 个候选及原始引用仍在，第 17、21 分镜的 0.484094× 和 3.469469× 倍速保持原值。另一个真实媒体工程完成了移动目录、取消、批量重新定位、新格式保存重开、预览和导出，输出 1.1 秒 MP4 并解码核对红色测试画面。

混剪输出使用 FFmpeg 的 libx264 软件编码。设置中的「兼容模式（软件渲染）」影响编辑器的屏幕绘制，开启后重启生效。连续快速拖动播放头时另发现，Windows 已解码正确目标帧，暂停的原生显示表面仍可能显示之前的帧。本版在暂停时保留目标帧，经有色画面采样验证。此前截图对应原工程第 3 分镜首尾共 5 帧无画面且音频继续。要判断同事所说的第二条变体是否还存在另一处白闪或跳帧，需要那条异常 MP4。

## 性能记录

60 Hz、100% 缩放、1400×900 窗口，系统使用 RTX 4060 和 RTX 3060。大工程中，滚动 1,000 条预览的 P95 为 17.0 ms，拖动候选为 49.9 ms，移动播放头为 83.3 ms，调整面板为 16.8 ms，缩放时间线为 216.6 ms。大工程拖动、播放头和缩放仍超过每帧约 16.7 ms 的目标。标准工程中缩放为 16.9 ms，播放头为 33.3 ms。逐场景超过 25 ms 的帧数、旧版对照和原始 JSON 见[前台交互基线](benchmarks/README.md)。

## 本地验证

在单独的临时目录执行 npm ci 成功。175 项 Node 测试通过；Windows 桌面冒烟 4/4 通过，用时 49.2 秒。全量桌面场景 31/31 通过。检查包括真实 FFmpeg 解码编码、重新定位后的成片以及旧草稿保存重开。四个核心文件通过 TypeScript 检查，源代码、脚本与测试通过 ESLint。

## 界面验收

三个右键菜单在深浅主题和不同底色的文字对比度抽样最低为 5.93∶1。对 8 组尺寸、缩放和主题截图逐张验证播放器已解码显示合成素材。时间线及面板边缘保留精细拖动区，同时在「调整布局 → 面板尺寸」和「编辑工具 → 调整轨高与面板尺寸」提供同功能的大控件。11 个面板把手均验证 32×32 像素区域四角命中，7 项实测拖动与撤销，4 项实测跨栏切换；三条轨道可通过数值调整或恢复默认高度。抽样覆盖剪辑台常用入口。

## 交付安装包

Windows x64 离线安装包大小为 383,063,816 字节，SHA-256 为 `f680909f1e167a8f2d2f145bdb377349fcf4e436066533d94e96f974b1b3db28`。从最终 EXE 中解出 app.asar，109 个运行文件与工作区逐字节相同。用随包佳剪.exe 和独立用户目录实际启动两次，核对首页、剪辑台、工程 v2 保存重开，以及切换兼容模式后重启确已关闭硬件加速。安装包未代码签名，未在使用者机器上安装或卸载。该构建沿用已核验 SHA-256 的既有 Windows 缩略图 DLL，构建机未安装 Visual Studio C++ 编译器。
